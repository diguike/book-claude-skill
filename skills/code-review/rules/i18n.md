# 国际化 (i18n) 审查规则

审查包含文案字符串或 i18n 函数调用的代码时使用。

## 1. 不要硬编码文案

所有面向用户的文案都应通过 i18n 函数获取，不要直接写中文/英文字符串。

- ❌ `<button>提交</button>`
- ✅ `<button>{t('common.submit')}</button>`
- ❌ `alert('操作成功')`
- ✅ `alert(t('message.success'))`

例外：日志、错误消息（面向开发者的）可以用英文硬编码。

## 2. 不要拼接文案

不同语言的语法结构不同，字符串拼接在翻译后可能语序错乱。

- ❌ `t('you_have') + count + t('messages')` — 中文"你有3条消息"没问题，但英文语序不同
- ✅ `t('you_have_messages', { count })` — 翻译模板自己处理语序

## 3. 日期和数字格式

- 不要硬编码日期格式（`YYYY-MM-DD` 不是所有地区的习惯）
- ❌ `format(date, 'MM/DD/YYYY')` — 美国格式，欧洲人看不懂
- ✅ `new Intl.DateTimeFormat(locale).format(date)`
- 数字的千位分隔符各国不同（美国用逗号，德国用点号）
- ✅ `new Intl.NumberFormat(locale).format(number)`

## 4. RTL（从右到左）支持

- 如果产品面向阿拉伯语/希伯来语用户，布局要支持 RTL
- 使用逻辑属性：`margin-inline-start` 而不是 `margin-left`
- Flex 布局天然支持 RTL（设置 `dir="rtl"` 即可）

## 5. 文字长度

- 翻译后的文案长度可能差异很大（德语通常比英语长 30%）
- 按钮和标签不要依赖固定宽度
- 使用 `min-width` 和 `text-overflow: ellipsis` 做兜底
